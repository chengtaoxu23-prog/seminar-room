# 约 90 秒演示脚本

## 演示前 30 秒检查

- 已运行 `npm run dev` 或 `npm run build && npm start`。
- 打开 <http://127.0.0.1:4317>（开发模式用 <http://127.0.0.1:5173>）。
- 若 `.env.local` 已配置真实模型，首页右上角应显示模型名，表单可提交。
- 若没有密钥：只演示“示例回放”，并在开头明确说“这是预置示例，不是实时模型”。不要声称真实调用成功。

---

## 0:00—0:08 开场

**画面：** 首页。

**说：**

> 这是一个范围很小的开源实验：把一段材料变成可参与的 AI 研讨，不是生成课件。
> 三个角色有独立上下文，主持人逐步决定下一步；用户可以随时打断。

---

## 0:08—0:22 载入材料，生成三问

**操作：**

1. 点击右侧第一张卡片“共学空间的开放时间” → “载入材料”。
2. 指出主题已填入：“共学空间是否应把周五最低开放时长延长到 24:00？”
3. 点击“生成三个问题”。

**说：**

> 材料会被编号分段。这里的三个问题是真实模型调用，不是模板；生成后可以改。

---

## 0:22—0:32 确认问题，开始

**画面：** 准备页。

**操作：** 快速指出三个问题；可把第一题改成“先核对 22:00 后的真实需求”。点击“开始研讨”。

**说：**

> 主持人会先读材料索引，再决定请谁发言；角色之间只交接结构化任务，不交接一条共享聊天记录。

---

## 0:32—0:50 真实三角色

**画面：** 讨论区出现主持人、A、B。

**说：**

> 主持人的动作是 invite / clarify / end，参与者返回带段落编号的逐字引用。
> 左侧是材料，点“材料 2”会定位并高亮原文；右侧的共识与分歧要等结束后才由独立总结员生成。

**操作（可选）：** 打开“技术记录”，指出不同角色的上下文指纹、耗时和 token；不要停留超过 5 秒。

---

## 0:50—1:02 用户插话

**操作：**

1. 在底部输入：“如果只在周五延长到 23:00，而不是 24:00，成本能降多少？请直接回应。”
2. 发送。
3. 指出主持人下一句明确把用户消息列为安排，参与者卡片出现“直接回应你”。

**说：**

> 用户插话后，主持人不能再按原剧本点名；服务端会校验用户消息 ID 是否被安排，参与者要在 addresses 中确认。

---

## 1:02—1:12 暂停与结束

**操作：** 点击“暂停”，指出状态“已暂停”；可等待当前调用结束。再点击“继续”。然后点击“结束”，确认。

**说：**

> 暂停后不再调度新调用；结束会中止在途请求，之后只允许一次独立总结，不再有角色调用。

---

## 1:12—1:28 总结与编辑

**画面：** 右侧总结出现。

**操作：** 修改第一条共识，点击“保存编辑”；指出“已人工编辑”。

**说：**

> 总结分为共识、分歧、材料依据、未解决；依据再次逐字核对。编辑会写回服务端。

---

## 1:28—1:30 导出与收尾

**操作：** 点击导出 Markdown（或展示底部按钮）。

**说：**

> Markdown 和 JSON 都从实际会话状态导出，包含技术记录；没有密钥时，示例回放会明确标注非实时模型。

---

## 无真实密钥时的 40 秒替代演示

1. 首页点击“示例回放”；
2. 指向顶部琥珀色提示：“示例回放 · 非实时模型输出 / 预置脚本 / 0 次实时模型调用”；
3. 点击“显示完整回放”，指出用户插话后的“直接回应你”；
4. 打开右侧总结，点击一条“材料 2”引用定位原文；
5. 收尾：

> 这是预先编写的回放，用来展示交互；它不证明模型能力。真实模型的验收需要服务端 API 密钥，当前交付明确记录为阻塞项。
