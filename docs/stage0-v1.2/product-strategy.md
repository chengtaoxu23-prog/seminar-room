# SeminarRoom V1.2 产品策略
2026-11-08 · 阶段0正式设计基线；产品仍是Alpha，阶段1未启动。

## 定位与核心价值
**AI Research & Collaboration Workspace**。用户创建和管理持久化机器人Agent，团队围绕共同目标分析、分工、执行、交接、核验、修订并交付。AI团队围绕目标开展工作是产品核心；Artifact是工作流产生的可验证、可编辑、可交付成果。教学研究是首个内置应用，后续扩展其他研究、分析和写作，不要求重写底层引擎。

首要场景延续已有材料驱动的教学研究：教师、助教或学生提出目标与共同材料，团队形成能审阅的教学方案，同时保留证据、分歧、未解决问题与执行记录。国内可实际测试的模型优先，语言、时区、Base URL和提供商适配保持可配置。

## 四组必须区分的概念

| 概念 | 边界与验收依据 |
|---|---|
| AI工作流 / 聊天交互 | 工作流包含目标、Task、依赖、Run、交接、恢复和验收；聊天是沟通/介入通道之一。消息数量不代表任务完成。 |
| 多模型调用 / Agent协作 | 多模型仅证明不同推理后端被调用；协作还必须实际消费彼此的任务结果、依据证据反馈修订，并共同推进交付。轮流发言不满足完整协作验收。 |
| Agent身份 / 底层模型 | AgentProfile持久存在；Membership表达项目职责/权限；ModelConnection是可替换后端。同一模型可以服务多个Agent，同一Agent可更换模型但保留身份与历史。 |
| 研究过程 / 最终成果 | Session、Task、Run与消息记录过程；Artifact/Version承载可接受或拒绝的成果。保存草稿不代表批准交付，批准成果也不代表批准外发。 |

## 核心工作链
用户目标 → Coordinator分析与约束 → 任务分解 → Agent选择/项目成员分工 → 执行 → 结构化交接与反馈 → 结果整合 → 证据核验 → 候选版本人工审批 → 成果交付。
Coordinator是协调职责，可由持久Agent承担；Router是调度机制；两者都不绑定固定厂商或模型，也不要求永远另建一个机器人。任务可以跨Session持续存在。人类观察状态、介入方向、暂停/终止、修改验收标准和批准特定候选，不负责机械推进每条Agent消息。完整契约见[user-workflows.md](user-workflows.md)。

## 当前能力账本

| 状态 | 能力 | 事实边界 |
|---|---|---|
| 已实现于Alpha | 文本分段、三个问题、固定host/a/b独立上下文、结构化发言交接、用户插话、引用、暂停/继续/结束、总结编辑、保存与MD/JSON导出 | 以具体代码版本及测试为准；不称完整自主Agent工作流 |
| 历史真实运行 | 2026-11-07同一qwen-plus配置的教学备课案例 | 已有公开状态文档记录；本轮不重跑，不代表跨模型或教学效果验收 |
| 仅原型 | 八页亮色UI、合成项目/机器人配置/连接/Task/Run/候选审批/版本、工作流蓝图 | 没有生产后端，没有自主执行，没有真实模型请求 |
| 规划中 | 阶段1项目闭环；阶段2多模型与持久身份；阶段3自主任务；阶段4共同研究写作；阶段5持久执行与工具/记忆 | 本次发布的是设计基线，不是这些功能上线 |
| 待验证 | 国内不同模型实际协作、跨厂商能力、真实暂停恢复、学习效果与长期稳定性 | 真实调用另须授权，成本和效果不填虚构数字 |

本地含用户未提交修复的工作版本与公开main不是同一代码基线；六项关键回归修复的同步状态必须分别记录。设计发布不会顺带发布那些生产改动。

## 差异化与取舍
保留持续研究项目、稳定机器人身份、证据可追溯、任务交接与可控执行。成果质量衡量工作流价值：从目标到被接受成果的时间、任务成功/恢复、无效重复、引文核验、人工修订与每份成果的资源消耗。只有同材料/约束/预算下对照单模型，才讨论协作增益；不以Agent数量、Token或更长答案作为收益。

必须：正式基线内部一致，八页和三路径可检查，执行与可靠性契约清楚，多模型阶段2不可无限后移。选做：连接健康与人工切换。可延期：原生国际Adapter、多人实时协作和高级工具；不得以这些扩展阻塞阶段2国内兼容连接。

阶段0到此停止。当前授权包括文档/必要原型修订及GitHub提交推送，不包括阶段1生产开发、真实调用、部署替换或发布Release/Tag。
