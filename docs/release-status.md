## 2026-11-07 真实研讨案例

2026-11-07，使用千问 `qwen-plus`（`dashscope.aliyuncs.com`）完成书法教学备课研讨：“一节90分钟毛笔书法入门课，如何兼顾看清示范、动手练习与个别反馈？”实际运行 **6轮、14次模型调用、42,495 tokens**（输入37,444，输出5,051），包含用户插话、参与者直接回应、独立总结、人工编辑保存及 Markdown / JSON 导出。

案例在已做千问适配的本机工作版本运行；适配代码不属于本次四份文档提交，不能将该案例当作公开 main 所有配置均已通过验收的证明。

输入情境为助手自拟：8名零基础成人、1位老师、90分钟，无投影与助教；不是教师真实课堂数据。讨论出现假设被误标为事实、总结扩大原意或遗漏后续立场变化的问题，助手通过插话纠正并人工编辑了总结。它展示可用流程，不证明教学建议正确。

这是一次人工操作的真实运行案例，不等于 `npm run check:live` 自动化实模验收通过；目前仍未生成该脚本的 `docs/live-run.json` 报告。案例没有验证真实模型下的暂停/继续、长期稳定性、教学效果或多模型协作。三角色使用同一个模型和同一套服务配置，通过独立上下文分别调用。

## 产品定位与后续方向

**教学研究是 SeminarRoom 的第一个内置产品**，当前通过材料、三问、三角色研讨和总结导出这条通用流程，服务教学备课与方案比较；尚没有独立的教学研究模板或专用模块。

多 API Key、多模型协作、自主分工、共同研究与写作、界面优化是未来发展方向，尚未实现或验收。当前的主持人调度是既定角色内的发言安排，不代表 Agent 已能自主组建团队、分解研究任务或联合写作。

## 能够展示什么

- 材料分段、三角色独立上下文与结构化交接的实现；
- 用户插话、引用核对、暂停结束、总结编辑与导出的产品流程；
- 明确标注为预置脚本的示例回放；
- 自动化测试及架构取舍。

## 尚不能声称什么

- 真实模型已稳定运行或已验证讨论质量；
- 已产生学习效果、用户增长或真实用户使用数据；
- 已可部署为公网多用户服务。

仍无自动化实模验收报告 `docs/live-run.json`。本地已保存书法案例的真实运行截图与导出，但本次仅更新四份文档，不将这些附件纳入仓库；原截图目录仍是历史回放与 mock 证据。后续需补齐自动化实模验收。

## 数据处理

会话保存在本地 `data/`；配置模型后，相关材料、发言和问题会发给用户所配置的模型服务商。API 密钥由本地后端读取。整个 `data/` 目录和本地环境文件应排除在 Git 提交之外。
